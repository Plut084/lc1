# 物品相关细则

**注：为方便理解，本文将所有可进入背包的项目统称为物品，物品包括道具和装备等（暂时只有这两种）。**

- 背包、装备栏和物品出现方式参考[背包物品.md](背包物品.md)。本文补充堆叠、丢弃、使用和不同人物之间的转移。
- 下文未在原文中明确的数量、距离和计算方式均为首版拟定值，便于讨论和配置，不代表已经实现。

# 配置需求

### 配置相关

- 主要通过以下几个表来配置
  - [basicbag.yaml](config/basicbag.yaml)，负责背包通用逻辑。可选，不配置时使用本例中的默认值。
  - [bags.yaml](config/bags.yaml)，负责不同背包的差异。
  - [equipments.yaml](config/equipments.yaml)，负责头盔、胸甲、靴子等装备。
  - [weapons.yaml](config/weapons.yaml)，负责近战武器、远程武器。武器也属于装备，不在装备表中重复配置。
  - [normal.yaml](config/normal.yaml)，负责消耗道具、材料等普通物品。
  - [buff.yaml](config/buff.yaml)，负责背包特殊能力、超重惩罚和道具使用效果。
  - [model.yaml](config/model.yaml)，负责模型资源引用。尚未接入时可为空，使用统一拾取标识。
- 示例表使用英文key、中文注释。属于需求配置样例，尚未接入程序；现有运行时表的字段另行适配，不直接替换。
- 每个表包含一至两个实例。模型和图标资源名为示意，需由后续资源制作提供。

- **物品通用字段**
  - id，int，唯一key。equipments.yaml、weapons.yaml、normal.yaml三个表之间不可重复。
  - 名称（name），string，用于背包列表和tips显示。
  - 图标（icon），string，图标名。为空时使用统一占位图。
  - 种类（type），枚举，分为装备（equipment）、道具（normal）。武器的种类也填写equipment。
  - 重量（weight），float，单位重量，单位为g克。需大于0。
  - 描述（description），string，为空时无描述。
  - 模型（model），int，引用model.yaml。为空时使用统一拾取标识。
  - 堆叠上限（max_stack），int，需大于等于1。装备固定为1。
  - 可丢弃（discardable），bool。为false时不可主动丢弃。
  - 可转移（transferable），bool。为false时不可转给其他人物。

- **装备和武器补充字段**
  - 部位（slot），枚举，近战武器（melee）、远程武器（ranged）、头盔（head）、胸甲（chest）、靴子（feet）。
  - 穿戴力量需求（required_strength），int，为0时不限制。
  - 护甲（armor），float，配置于equipments.yaml。
  - 攻击（attack），float，配置于weapons.yaml。
  - 攻击距离（range），float，单位为米，配置于weapons.yaml。
  - 首版不在此展开耐久、随机词条和强化。

- **道具补充字段**
  - 可使用（usable），bool。材料等不可使用的道具填写false。
  - 使用效果（use_buff），int，引用buff.yaml。可使用道具必须配置；不可使用时为空。
  - 每次消耗（consume_count），int，可使用时需大于等于1；不可使用时为0。
  - 使用冷却（cooldown_seconds），float，单位为秒。为0时无冷却；按人物和物品id分别记录。
  - 使用对象首版固定为持有该物品的人物，不额外配置目标类型。

- **背包补充约定**
  - bags.yaml包含id、name、special_buff、overweight_buff、model、icon、description。
  - special_buff和overweight_buff均引用buff.yaml，为空时无对应效果。
  - 背包容量不在bags.yaml中单独配置，由人物力量和basicbag.yaml共同确定。
  - 页签、排序、容量计算、拾取距离、转移距离等通用值详见basicbag.yaml中的注释。
  - buff.yaml的effects为效果列表。首版示例支持恢复生命（restore_health）、移动速度倍率（move_speed_multiplier）。
  - duration_seconds为持续秒数。恢复生命使用0，立即结算；背包和超重效果使用空值，由穿戴及超重状态决定何时移除。
  - model.yaml的id为模型key，resource为资源路径。

# 堆叠与重量

### 逻辑相关

- **堆叠**
  - 相同物品id的道具可以堆叠，不同id不可合并。装备每件占一条。
  - 入包时优先补满已有堆叠，剩余数量再新建条目。列表暂时不限制最大条数。
  - 例如堆叠上限为20，当前有18个，再获得5个，则显示20个和3个两条。
  - 堆叠只是显示和管理方式，不会减少重量。
  - 数量只接受正整数，减少至0后移除对应条目。

- **重量与容量**
  - 一条物品的重量为单位重量乘以数量，总重量为所有条目的重量之和。
  - 首版拟定基础容量为10000g，每点力量增加1000g，力量按不小于0计入。具体值可在basicbag.yaml中修改。
  - 容量只计算背包内物品，不计算已穿戴装备和背包自身。卸下装备时需要检查入包后的重量。
  - 总重量等于容量时仍可正常持有；超过容量时触发当前背包配置的超重惩罚，不叠加触发。
  - 力量降低等原因可使已有物品超重，不自动丢弃。超重时不能通过拾取、发放和转移继续增加重量，仍可使用、丢弃和转出。
  - 换背包沿用原文规则：原背包掉落，物品按当前列表顺序转入新背包，容量不足的部分掉落；可堆叠道具按可容纳数量拆分。
  - 此处可丢弃限制只约束主动丢弃，换包溢出仍按原文执行。不可丢弃物品也可能因换包溢出掉落，首版不将其视为绑定物品。

# 丢弃

### 逻辑相关

- **单件与批量丢弃**
  - 在背包中右键点击物品，选择“丢弃”。装备和道具使用相同的丢弃逻辑。
  - 数量为1时直接丢弃；数量大于1时打开数量窗口。
  - 数量窗口默认选择1，可输入数量或点击“全部”，允许范围为1至该条目当前数量。
  - 不可丢弃时，“丢弃”按钮置灰，提示“该物品不可丢弃”。
  - 已穿戴装备需先卸下，再从背包中丢弃。

- **丢弃结果**
  - 在物品持有者附近的有效地面位置生成掉落物，不使用当前操作人物的位置代替。
  - 生成成功后，才从背包中扣除数量并更新重量。附近无有效位置时，本次不丢弃，提示“当前位置无法丢弃”。
  - 堆叠道具丢弃部分数量后，剩余数量保留在原条目。丢弃全部后移除条目。
  - 丢弃后按原文中的掉落拾取逻辑处理，不按现实时间自动消失。
  - 首版没有物品销毁入口，丢弃不等于直接删除物品。

### 界面相关

- 数量窗口包含物品图标、名称、可丢弃数量、数量输入、“全部”、“确定”和“取消”。
- 确定后关闭窗口并更新列表；取消时不改变物品。
- 操作期间数量变化时，按确认时的实际数量检查。数量不足则提示并保留窗口，更新可选范围，不直接扩大或缩小本次选择。

# 使用

### 逻辑相关

- **道具使用**
  - 可使用道具的右键菜单显示“使用”；不可使用的道具不显示该项。首版不考虑礼包类道具。
  - 点击后由持有该物品的人物使用。切换人物查看背包时，不能把效果加给当前玩家操控的其他人物。
  - 每次只执行一次使用，不提供批量使用。
  - 使用前检查人物可操作、物品数量满足每次消耗、冷却结束，且使用效果可生效。
  - 首版人物死亡或被俘时不可使用；受伤不阻止使用。其他状态限制暂不展开。
  - 例如恢复生命道具，在生命已满时提示“当前无需使用”，不消耗数量，也不进入冷却。
  - 效果成功结算后，扣除配置数量并进入冷却；失败时不扣数量、不进入冷却。
  - 恢复量不能超过人物生命上限。使用完毕后同步更新数量、重量和人物属性。
  - 冷却按游戏时间计算，暂停时不推进，存档保留剩余时间；同一人物同id的不同堆叠共用冷却。

- **装备穿戴**
  - 装备使用原文中的“对比”和“穿戴”入口，不走道具使用效果。
  - 穿戴前检查部位和力量需求。同部位已有装备时，将其放回背包。
  - 计算替换后的背包重量，可容纳才整体更换；不能容纳时保持原穿戴状态，提示“背包容量不足”。
  - 应用预设时只查找该人物背包内的装备，不从其他人物或地面自动取得。缺失或不满足条件的部位跳过并提示，其余部位按上述规则执行。

### 界面相关

- 使用成功后保留背包界面，刷新当前人物信息。
- 冷却中的“使用”按钮置灰，并显示剩余秒数。物品不足和人物状态不允许时显示对应原因。
- 使用后数量为0，移除条目并关闭该条目的操作菜单。

# 不同人物之间的转移

### 配置相关

- 首版只支持玩家可管理、存活且未被俘的人物之间转移，可以跨小队选择。
- 双方需在同一已加载场景，距离不超过basicbag.yaml中的transfer_distance，拟定为5米，且中间没有阻挡。
- 不支持通过小队菜单远程传物。交易、赠送给非己方人物等另行设计。

### 逻辑相关

- **选择物品**
  - 点击背包中的“转移”，以当前查看人物为转出方，再选择一名其他人物为接收方。
  - 可同时选择多个物品条目，并分别填写数量。选择数量范围为1至对应条目持有数量。
  - “全选”选择当前页签下可转移的全部条目，不包含被筛选隐藏的条目。“全部数量”仅修改对应条目的数量。
  - 切换页签时保留已选物品，确认区展示所有已选条目，避免隐藏选择被遗漏。
  - 不可转移物品不可勾选，并显示原因。已穿戴装备需先卸下。
  - 转移不自动穿戴装备，也不触发道具使用。

- **确认转移**
  - 确认时检查双方状态、距离、物品实际数量和可转移标记，再计算整批总重量。
  - 接收方容量足够时才整体转移；不足时整批不执行，提示还需减少多少重量，由玩家调整选择。
  - 转移成功后，转出方扣除数量，接收方按堆叠规则入包，同时更新双方重量和列表。
  - 不生成世界掉落物，也不因容量不足自动掉落。
  - 数量变化、人物离开范围或接收方变为不可操作时，本次不执行，更新界面并提示原因。
  - 取消窗口或切换转出人物时清空本次选择，不改变双方已有物品。
  - 例如转移3个恢复药和1顶头盔，需要750g容量；接收方只有500g剩余容量时，整批不执行。

### 界面相关

- 转移页左侧显示转出人物背包，右侧显示接收人物及其当前容量，下方显示已选数量、总重量和转移后的预计容量。
- 接收人物从下拉列表选择，不可选人物置灰，并提示距离或状态原因。自己不可作为接收方。
- 点击条目旁的勾选框后可修改数量；未选物品不计入预计容量。
- 确认按钮显示“转移”，无选择或条件不满足时置灰；取消按钮关闭转移页。
- 成功后保留转移页、清空已选条目，方便继续转移。

# 保存与配置检查

### 逻辑相关

- 存档保存各人物的背包类型、物品id、数量、条目顺序、穿戴状态和道具剩余冷却。世界掉落物另外保存位置及剩余数量。
- 总重量、最大容量、背包特殊能力及超重惩罚根据读档后的配置和人物属性重新计算，不重复叠加效果。
- 配置加载时检查重复id、必填字段、枚举、数量与重量范围，以及buff、model引用是否存在。错误应指出对应文件、物品id和字段。
- 图标和模型资源尚未提供时使用占位显示；非空的buff或model编号仍需能在对应表中找到。
- 未知物品id的旧存档处理方式另行确定，首版不静默删除物品。
