# 主场景性能定位（2026-10-02）

本次针对 `make run` 默认 Debug 的卡顿进行测量。主要回退来自展区新增的五盏灯全部参与
ray-query 阴影和逐采样材质计算；validation 与 synchronization validation 又带来明显的 CPU 开销。
之前的运行验证只检查正确性，没有验收帧时，这是展区上线时遗漏的检查。

## 测量方法

- GPU：NVIDIA GeForce RTX 4060 Laptop，Vulkan 1.4.341。
- 最近主程序日志中的 framebuffer 为 1882×2032，约 382 万像素；创建窗口请求的 1280×720
  约为 92 万像素。Wayland 窗口管理器可以改变实际尺寸，不能用请求尺寸估计负载。
- 固定出生点斜视相机，使用当前大陆、展区和相同的八盏灯。为了保持测量确定性，省略玩家单个绘制项，
  共 242 个 draw；原场景对照为 168 个 draw、三盏灯。
- 在临时源码副本中插入 Vulkan timestamp query，分别测量 TLAS、阴影可见度、时间累积、空间滤波、
  PBR+HDR resolve、色调映射。项目渲染源码没有加入测量开关。
- 每组预热 12 帧、测量 24 帧，报告中位数。CPU 计时覆盖命令录制及其间的资源更新。
  测量程序每帧等待 fence，便于准确读回 query，**其串行帧时不能直接换算成正常多帧并行程序的 FPS**。
- 桌面后台负载、时钟、视角和分辨率都会影响绝对值；重复默认配置得到约 30.6～31.0 ms GPU 时间。
  一次 Release+validation 启动遇到 Wayland 连接失败，重试成功；失败样本不纳入结果。

固定 1882×2032、4× sample shading、八盏灯、动画开启，validation 与同步验证开启：

保持展区几何不变，新增五盏灯带来约 17.1 ms GPU 增量。保持三盏灯不变，新增几何带来约 3.5 ms 增量。
暂停动画几乎没有改善；TLAS 重建不是本次主要瓶颈。降低 MSAA 可节省约 4.3 ms，但阴影负载仍在。
Release 明显降低 CPU 录制成本，GPU 耗时基本相同，不能单靠换构建类型解决 GPU 瓶颈。

补充对照（Debug、关闭 validation）：球形灯每帧采样由 2 改为 1，GPU 为 27.69 ms；
所有球形灯半径改为零，使空间滤波提前返回且阴影变为硬阴影，GPU 为 22.49 ms。
这些只是诊断对照，并未修改默认画质。

## 对应代码

- `app/main.cpp` 把展区五盏灯插入原三盏灯，默认模式为“全部”。
- `shaders/shader.slang::visibilityMain` 对每盏有贡献的灯计算阴影；
  `shaders/ray_shadows.slang::shadow_visibility` 对球形光执行多条射线。
- `src/vk/ray-query-shadows.cpp::record` 每帧执行可见度、时间累积、空间滤波。
- `shaders/spatial-shadows.slang` 在有球形光时遍历 5×5 邻域，再对相关灯累加权重。
- `src/vk/pipeline.cpp` 的 `minSampleShading = 1.0` 让 4× MSAA 按四个采样点执行材质光照。
- 全大陆和展品目前都提交绘制；只动两个展品也会重建整个 TLAS，但实测 GPU 代价很小。

## 优化优先级

1. 给阴影明确预算：区分关键投影灯与辅助补光，或设计按需更新、静态缓存机制。
   补光是否投影需要作为显式画质选择，不能用距离截断偷偷改变现有无界平方反比光照。
2. 优化阴影邻域滤波中的重复读取和逐灯计算；评估降低阴影分辨率时的边缘与时间稳定性。
3. 评估主通道 sample shading，以及绘制顺序造成的重复着色；保留可见的质量对照。
4. 开发时继续保留验证默认开启，性能验收另用 Release／无验证测量，并记录实际 framebuffer 尺寸。

原始结果和临时测量程序位于本次环境的 `/tmp/lc1-profile/`，没有修改默认渲染设置。
